## 如何持续更新

每份笔记区分以下信息，不把它们混成同一种事实：

- **简历表述：** 简历里已有的工作声明，作为面试需要解释的范围；不是源码核验结果。
- **材料可见：** 用户提供的设计说明或片段记录了什么；说明可能省略细节或存在错误，不自动等于当前固件行为。
- **已确认的个人职责：** 用户明确说明自己实际完成的部分；维护、调用、调试、整理与从零实现分别描述。
- **背景解释／设计建议：** 帮助理解原理或改善方案，不写成项目已实现的功能。
- **待核实：** 需要代码、配置、原理图、日志或本人补充才能确定的细节。

后续拿到材料后，在对应经历内补“文件／函数 → 输入输出 → 调用链 → 证据 → 面试回答”；实际确认后再更新状态。没有测试记录时，不补造时延、准确率、稳定运行时长、提升百分比或根因结论。

## 面试准备方式

每段经历先准备一个可追问的一分钟版本，再选两条最熟的技术链路展开。回答按“目标 → 自己负责的部分 → 设计与取舍 → 定位证据 → 验证结果”组织。具体实现待确认时，如实说明，随后解释原理与准备怎样验证。
