## 2. 信号与控制链路

```text
竞赛阶段：
赛道电磁信号 → 六路电感及模拟调理 → ADC → 滤波／归一化
 → 位置偏差 error → 转向 PD → 舵机
轮速目标与反馈 → 速度控制 → 电机驱动

拓展阶段：
编码器 → 左右轮速 ─┐
MPU9250 → 姿态／航向 ├→ 差速控制与状态估计 → 电机命令
                    └→ XY 轨迹 → UART／HC-12 → Qt 可视化
```

具体定时来源、控制周期、传感器读取方式和 ISR／主循环分工待确认。实时控制应说明“谁在何时更新数据并执行控制”，不能只列出 PID、DMP、ADC 等名词。

### 2.1 论文拓展阶段的硬件与外围职责

整理材料转述 STM32 定时器承担编码器计数、PWM 和周期调度，I2C 访问 MPU9250、OLED、AHT20，USART 连接 HC-12；电机驱动使用 L298N。AHT20／OLED 是辅助监测，不与前一个空气质量项目的 DHT11／ST7735 混用。

- **型号与资源：** STM32F103 完整后缀尚未确认，不能把整个系列统一写为 64 KB SRAM；例如 x8／xB 型号为 20 KB。具体定时器、ADC 和引脚以实际型号及初始化为准。
- **H 桥与 PWM：** 方向输入决定电机电压极性，PWM 调节驱动；制动／滑行要按输入与使能组合确认。相同占空比不保证左右轮同速，这也是编码器反馈的意义。
- **L298N：** 评估导通压降、发热及电流能力；具有 Sense 引脚不等于模块已经实现过流闭环或完整电流控制。
- **供电：** 材料提到电池、5 V／3.3 V 和 MP1584EN 降压；预算应考虑电机启动／堵转及逻辑供电干扰。压降、地线扰动是待测量的排障方向，不直接认定为某次故障根因。
- **辅助监测：** 材料描述 AHT20 温湿度、OLED 显示与报警；读取等待和刷新应与控制周期分离，告警提示与停车策略也应分别定义。

## 3. 六路电感、ADC 与偏差计算

每路信号从模拟调理到 ADC 数字结果，应能解释量程、偏置、饱和、噪声和通道一致性。需要确认采样是否定时触发、使用扫描／DMA 还是轮询，各通道是否足够同步。

归一化用于减少不同通道增益和安装差异，滤波用于降低噪声，但滤波会引入延迟。滤波算法、窗口和时间常数必须从代码确认，不能泛称“滤波以后更准”而不说明对控制响应的影响。

一种**仅用于解释的加权位置示例**：

```text
error = Σ(w_i × s_i) / Σ(s_i)
```

这里 `s_i` 是经过实际算法处理后的通道强度，`w_i` 代表位置权重。它不是本项目已核实的公式；实际可能是差比和、左右通道组合或分段规则。分母接近零时必须有处理，还要定义丢线、交叉区域、尖弯及信号饱和等状态。

要补一组“六路原始值 → 处理后数值 → error → 控制输出”的真实样本，才能把算法讲具体。

### 3.1 ADC／滤波新增复习点

典型电磁采集链是感应信号经放大、选频／检波等调理后进入 ADC；原始交流信号与调理后的幅值不是同一个量，实际电路未给出，不能直接认定某套滤波链已经实现。

N 位 ADC 的理想量化间隔约 `Vref / 2^N`，12 位、3.3 V 时约 0.806 mV；端点换算常写作 `V ≈ code × Vref / 4095`。量化间隔不是实测精度，还受参考、噪声和前端影响。多通道顺序扫描即使用 DMA，也通常存在通道间时差；需核对触发、通道顺序、采样时间、源阻抗和循环缓冲交接。

移动平均有窗口延迟，中值滤波适合孤立尖峰，一阶低通平滑但会滞后；都不能自动消除传感器偏置或丢线。分母接近零时需独立判断信号有效性，不能仅加 epsilon 后继续输出貌似正常的循迹误差。

## 4. 速度环、转向 PD 与调参

### 4.1 控制结构

整理材料的正文描述轮速 PI 与编码器反馈，附录另有经验 PWM 映射片段。解释闭环应沿“目标轮速 → 误差 → 控制器 → 电机 → 编码器反馈”核对完整调用，不能只靠 PWM 多项式证明最终实机闭环已成立。

若链路为“循迹偏差 → PD → 舵机目标角度／PWM”，这属于外层循迹转向控制，不自动等于本人实现了舵机内部的角度闭环。转向 PD 典型作用为比例响应偏差、微分抑制快速变化，但实际符号、离散实现和输出限幅要与车体方向一致。微分对噪声敏感，采样周期、滤波和执行器饱和都影响效果。

### 4.2 “分段／模糊 PID”到底指什么？

- 按偏差或弯道状态切换几组参数，可能更准确地叫分段控制或增益调度。
- 如果确实采用模糊控制，应说明输入、隶属函数、规则、输出参数以及如何映射到离散控制器。
- 不要只因为参数会改变，就宣称实现了完整模糊推理或自适应控制。

调参应准备真实过程：先确定方向和限幅，再逐步调整响应，观察直道、入弯、出弯及不同速度；用实际误差／轮速／输出曲线说明振荡和超调。没有对照记录，不补造“误差下降多少”或竞赛成绩。

### 4.3 编码器测速、方向与标定

AB 正交相位先后用于判断方向，增量计数用于测速。若电机轴编码器线数 P 尚未包含倍频，解码倍频系数 m、减速比 G，则轮轴每转计数可写 `N = P × m × G`；厂家若已给出解码后计数，不能再重复乘 4。

```text
采样周期 Ts，周期内有符号计数增量 ΔC，轮直径 D：
rpm = ΔC × 60 / (N × Ts)
v_wheel = ΔC × π × D / (N × Ts)
Δs = ΔC × π × D / N
```

整理材料转述的附录参数为 `JSB=2112`、轮直径 `D=0.0666 m`、轮距 `B=0.1261 m`、`Ts=0.01 s`，并出现 `Speed = Encoder × 6000 / JSB`。其中 `6000=60/0.01`；JSB 在此承担轮轴每转计数，具体编码器线数和减速比来源仍待确认。这些是片段参数，不是通用于竞赛车和所有代码版本的已测标定值。

演算例：10 ms 内计数 100，上述 N、D 下约 284.1 rpm、0.991 m/s；不是实测成绩。

保留计数与速度符号，倒车和原地转向不能取绝对值。低速时短周期内计数少，会有量化波动，采样更快不一定更好；可按需求比较定时计数、计周期或滑动窗口。计数回绕／读后重置要看驱动，材料中 `Read_Encoder()-30000` 不能单独证明完整计数策略。

标定先核对轮轴一圈计数，再用实际距离校准有效轮径，用旋转测等效轮距，并检查左右轮方向与尺度差异。轮胎变形、地面与打滑仍会影响结果。

### 4.4 论文轮速增量式 PI、降速与输出滤波

材料中的增量式 PI 可解释为：

```text
e[k] = 目标轮速 - 实测轮速
Δu[k] = Kp × (e[k] - e[k-1]) + Ki_d × e[k]
u[k] = u[k-1] + Δu[k]
Ki_d = 连续积分增益 × Ts
```

若采样周期已吸收进离散增益，不能再次乘 Ts；周期改变后也应重新核对参数。PI 可补偿持续的摩擦／负载误差，编码器噪声下加入 D 未必有益；增量式并非因为“速度有历史”才成为唯一选择。

材料描述根据偏差降速：`Vset = Vmax - error² × (Vmax-Vmin) / KsetV`。应结合误差单位和归一化设置参数，并限幅，防止大偏差生成过低或负速度。正文转述的 KsetV 范围 1000～3000 与示例代码 3600 存在差异，不能背成统一最终值。

输出一阶滤波片段为 `u_f[k] = 0.3u_f[k-1] + 0.7u_new[k]`；减小当前项权重更平滑，也更滞后。输出饱和时仍要考虑积分状态，增量式 PI 也不能自动避免 windup；积分限幅、条件积分或反算是可研究的改进，未证实原工程已采用。

### 4.5 方向模糊 PD：材料中的实际描述

输入是偏差 E 与变化量 EC，各分 7 个区间，形成 7×7 组合。完整隶属函数和 49 格规则尚未展示，不能凭“大误差增大增益”补出一套原规则。

```text
Fuzzy_out = Fuzzy(Error, Error - Error_old)
Kp = Kp_base + Fuzzy_out × Delta_P
Kd = Kd_base + Fuzzy_out × Delta_D
u_turn = Kp × Error + Kd × (Error - Error_old) + Kgyro × gyro_rate
```

该片段用同一个 Fuzzy_out 调整 Kp、Kd，不是两个已证实独立的规则表。差分未除 Ts 时，周期被吸收到 Kd 中；需要稳定节拍，并检查输入限幅、查表索引和增益范围。转向 PD 不加 I 的理由应结合过冲、持续偏差及饱和，不是“不考虑过去走过的路”。

这里属于毕业论文拓展控制的材料，不能替代竞赛阶段速度环分段／模糊 PID 的完整实现证据。补偿符号、物理量与前馈／反馈归属见第 6 节及代码复盘。

### 4.6 电流内环：正文描述与实现证据分开

整理材料转述速度 PI 外环给电流目标、电流内环输出 PWM，电流环 5 kHz、PWM 20 kHz，并有形如 `k1 × 电流误差 + k2 × 电流误差 × abs(电流误差)` 的占空比增量描述。电机转矩近似与电枢电流成比例，这是电流调节的意义，不等于专门的直接转矩控制 DTC，也不保证完全不打滑。

附录没有展示完整采样电阻／放大链、ADC 同步、中断调度和电流波形，因此不把它作为已验证实机高速内环。10 ms 轨迹控制不能替代 5 kHz 电流环；若继续核实，应分别查采样、标定、带宽、限幅和实际调用。

## 5. MPU9250、陀螺仪与姿态解算

**型号与边界：** 简历截图写的是 MPU9250；官方资料确认它是九轴运动传感器。简历还描述经 I2C 读取、调用 DMP 输出四元数并转换 roll／pitch／yaw。器件能力可以确认，整理材料有 DMP FIFO 与四元数转换片段，但项目是否读取磁力计、DMP 完整融合配置、输出率和坐标系仍需原论文／工程确认；不能因此写成九轴融合、绝对航向或姿态算法已独立自研。

### 5.1 九轴不是九个陀螺仪轴

```text
MPU9250 = 三轴陀螺仪 + 三轴加速度计 + 三轴磁力计
               3              3              3
```

陀螺仪本身仍是三轴；常说六轴组合通常指陀螺仪加加速度计，九轴再加入磁力计，描述的是测量通道，不是刚体有九个独立旋转自由度。MPU9250 的硬件具备九轴，不代表某个程序一定使用了全部九轴。

| 传感器 | 测量与常用单位 | 能提供什么 | 主要限制 |
| --- | --- | --- | --- |
| 陀螺仪 | 绕三轴的角速度，°/s 或 rad/s。 | 当前转动方向和快慢，用于快速动态跟踪。 | 角速度积分受零偏、噪声、温度与计时影响，可能漂移。 |
| 加速度计 | 三轴比力，g 或 m/s²。 | 静止／低动态时利用重力参考约束倾斜。 | 运动加速度和振动会干扰直接倾角估计，不能仅靠重力确定 yaw。 |
| 磁力计 | 三轴磁场分量，μT。 | 校准、倾斜补偿后提供相对地磁的航向参考。 | 受电机、电流、金属及外部磁场干扰，不是直接输出一个可靠的朝北角度。 |

“正在以 30°/s 转动”“目前相对参考偏了 60°”“目前位于某个 XY 坐标”是角速度、姿态和位置三个不同层次。

### 5.2 从寄存器整数到角速度，再到转角

传感器内部已完成信号数字化；主控通过数字接口读取结果，不需要再用 STM32 ADC 对它的角速度输出采样。读取陀螺仪原始有符号整数后，按实际配置的量程和灵敏度换算：

| 陀螺仪量程 | 典型灵敏度 LSB/(°/s) |
| --- | --- |
| ±250°/s | 131。 |
| ±500°/s | 65.5。 |
| ±1000°/s | 32.8。 |
| ±2000°/s | 16.4。 |

例如配置 ±250°/s，Z 轴原始值为 1310，则角速度为 `1310 / 131 = 10°/s`。这是器件换算例子，不代表项目实际量程。寄存器符号、字节顺序与比例因子要按相应传感器配置核对。

对近似水平、主要绕竖直轴转动的小车，可用单轴近似理解积分：

```text
本次角度 = 上次角度 + (测得角速度 - 估计零偏) × Δt
10°/s × 0.01 s = 0.1° 的本次角度增量
```

**零偏**指没有转动时仍存在的偏离零值的输出。若残留恒定偏差 0.5°/s，静止一分钟也会累计约 30° 角度误差；这只是教学计算，不是实测漂移指标。随机噪声、温漂、量程误差和不准确的 Δt 也会影响积分。

上述是单轴入门近似。一般三维运动中，机体陀螺仪三轴角速度不分别等于 roll、pitch、yaw 的变化率，需要姿态运动学变换或四元数更新，不能简单逐轴相加就宣称完成三维解算。

### 5.3 加速度计与磁力计怎样提供参考？

静止放在桌面上，加速度计读数的模长通常接近 1g，而不是三轴全零；按安装方向，某轴可能接近 +1g 或 -1g。倾斜改变重力参考在各轴的分量，因此静止／低动态时可估计 roll 和 pitch。具体符号取决于坐标定义。

加速、刹车、转弯和振动时，读数也受运动影响，不能始终把它当作纯重力方向。保持水平绕竖直轴旋转，重力参考不变，所以仅依靠加速度计无法确定绝对 yaw。

磁力计提供地磁参考，结合倾斜信息进行补偿，可约束航向；磁北也不等同于未经修正的地理真北。使用前通常需要处理硬铁偏置、软铁畸变、坐标对齐，并评估运行时干扰。

**与本车特别相关：** 电磁赛道线、电机、大电流走线和金属结构都可能干扰磁测量。因此需要确认是否实际用了磁力计、安装位置与校准方式，而不能只因硬件是九轴就保证航向长期不漂移。这里列的是风险来源，尚无项目实测证明具体故障原因。

### 5.4 姿态融合到底做了什么？

可以先理解为：陀螺仪跟踪快速转动，加速度计提供重力方向参考，磁力计在可信时提供地磁航向参考。算法综合测量与误差，估计姿态及可能的零偏等状态，而不是简单把九个数字求平均。

常见方法包括互补滤波、Mahony／Madgwick 类方法，以及卡尔曼／扩展卡尔曼等；它们是可选的算法类别，不代表项目都实现过。

单轴倾角互补滤波的教学形式：

```text
预测倾角 = 上次倾角 + 去零偏角速度 × Δt
融合倾角 = α × 预测倾角 + (1 - α) × 加速度计估计倾角
```

预测跟随快速变化，重力参考逐步约束倾角漂移；α 的选择还与采样率、噪声和动态需求有关。这个式子不等于完整三维融合，也不能用加速度计的倾角去修正绝对 yaw。

六轴姿态融合可以约束倾斜，但缺少其他航向参考时 yaw 通常仍可能漂移；加入磁力计也要评估磁干扰，不是所有工况下无条件信任它。滤波更强不一定控制更好，延迟和动态失真也要计入。

### 5.5 DMP、四元数和欧拉角分别是什么？

| 名称 | 含义 |
| --- | --- |
| DMP | 芯片内的数字运动处理单元，可在配置后承担部分运动处理，减少主控计算负担。 |
| 四元数 `q = [w, x, y, z]` | 三维姿态的一种表示，四个分量共同描述姿态，不是四个旋转轴；旋转四元数通常需单位长度。 |
| roll／pitch／yaw | 欧拉角姿态表示，分别便于理解横滚、俯仰、航向，但依赖坐标系与旋转顺序。 |

四元数适合内部三维计算，可避免欧拉角表示的某些奇异性；转为欧拉角便于上位机显示，但并不自动消除漂移。欧拉角仍需考虑奇异姿态、角度范围，以及跨 ±180° 时控制误差如何归一化。

要分清两种可能的计算路径：

```text
主控融合路径：读取原始数据 → 换算／校准 → MCU 上运行融合 → 四元数 → 欧拉角

简历描述的 DMP 路径：传感器采样 → 配置好的 DMP 处理
 → STM32 读取并解析四元数 → 按约定转换 roll／pitch／yaw
```

DMP 不是上电后自动输出任意想要的姿态结果：驱动／固件需正确初始化，配置输出及读取格式，按所用接口处理 FIFO 等。DMP 输出是否使用磁力计、表示相对姿态还是有外部航向参考，要看具体固件与配置；不能凭 DMP 名称断言内部采用了某个滤波器。

引用厂商 DMP／第三方驱动时，应说明自己的读取、校准、转换、异常处理和控制集成工作，不把厂商算法说成完全自研。

#### 5.5.1 新材料给出的 DMP 读取与 Q30 换算

```text
DMP 初始化／配置
 → dmp_read_fifo(gyro, accel, quat, timestamp, sensors, more)
 → 检查返回值与 INV_WXYZ_QUAT 有效标志
 → q[i] = quat[i] / 1073741824.0f
 → 按统一约定转换姿态角
```

分母是 2^30，材料采用的定点格式应做浮点换算，不能先整数除法。转述的项目封装返回 0／1／2 分别表示成功、FIFO 读取失败、无有效四元数标志；这不是所有 DMP 库统一的错误码。该片段显示 gyro、accel、quat 读取，不能据此证明磁力计已参与融合；FIFO 溢出、数据过期和时间戳异常仍应查完整实现。

#### 5.5.2 四元数转换补充：约定与数值保护

采用标量在前的单位四元数、常见主动旋转 ZYX 约定时，可用下列背景公式；实际必须统一转换方向、坐标与分量顺序：

```text
roll  = atan2(2(q0q1 + q2q3), 1 - 2(q1² + q2²))
pitch = asin(clamp(2(q0q2 - q3q1), -1, 1))
yaw   = atan2(2(q0q3 + q1q2), 1 - 2(q2² + q3²))
```

`atan2` 区分象限，`asin` 限幅避免舍入误差超出定义域，旋转四元数保持归一化。q 与 -q 表示同一旋转；四元数不是“XYZ 位置加角度”，也不能说单个四元数只能表示不超过 180° 的旋转。它比旋转矩阵少参数，但并不比三个欧拉角更省存储。

初始化减去起始 yaw 只是建立相对零点，不消除后续漂移。内部三角运算统一角度单位，姿态显示的 0.1° 分辨率也不能当成测量准确度。材料中的接口错位与单位混用见 [代码复盘](#thesis-code-review)。

### 5.6 实际采集、校准与数据检查

原工程的具体参数仍待确认，复盘时应沿下面流程查证：

```text
确认器件与接口 → 配置量程、采样率、滤波及需要的输出
 → 静止初始化／校准 → 按数据就绪或规定周期读取
 → 检查数据与时间戳 → 统一单位及坐标 → 输出给融合／控制／上位机
```

- **陀螺仪校准：** 静止条件下统计零偏并扣除，观察温度变化和后续漂移；静止均值不能直接当成对所有温度、所有工况永久有效的补偿。
- **加速度计校准：** 检查零偏、比例和轴间关系，可用不同静止朝向作基本检验；不能把正常的重力响应全部当作零偏减掉。
- **磁力计校准：** 处理硬铁／软铁及安装坐标关系，结合实际电机和赛道工作状态判断可信度。
- **时序：** 明确真实采样间隔，不能仅把任务延时值当作精确 Δt。FIFO 连续样本的时刻与主控集中读出时刻也不完全相同，要结合采样配置和接口管理。
- **一致性：** 检查新数据、FIFO 溢出／读取错误、量程饱和及轴方向；不要将不同传感器的不同更新率混成同一时刻的九轴数据。
- **坐标与单位：** 明确传感器坐标、车体坐标及世界坐标的关系，统一正方向、角度／弧度；不能因转换函数返回了数值就认为控制方向正确。

这些是验证与排查方向，尚未记录为项目已完成的校准方案或性能结果。

### 5.7 最终有哪些数据？在小车中分别怎么用？

```text
寄存器原始整数：acc_raw、gyro_raw、mag_raw
       ↓ 换算、校准、统一坐标
物理量：三轴比力／加速度、角速度、磁场
       ↓ 融合或 DMP 处理
姿态估计：四元数、roll／pitch／yaw
       ↓ 结合其他信息与运动学
控制输入、坐标变换、轨迹推算和显示
```

| 信息 | 在小车中的作用 |
| --- | --- |
| 电感解算的位置偏差 | 车相对赛道偏向哪一边，为循迹控制提供误差。 |
| 编码器轮速／里程 | 估计轮子转速和行进距离，用于速度反馈与里程计。 |
| 陀螺仪角速度 | 判断车身转动快慢，可参与转向动态控制或阻尼补偿。 |
| 估计的 yaw | 表示相对既定参考的航向，可用于平面轨迹推算。 |
| roll／pitch | 表示侧倾、俯仰，可供姿态监控或具体控制使用，项目实际用途待核实。 |

近似水平时通常更关注绕竖直方向的角速度；传感器实际安装轴要先变换到车体坐标，不能默认芯片 Z 轴永远就是车体竖直轴。

IMU 不直接输出可靠 XY 位置。可将编码器估计的短时距离 `Δs` 与区间航向 `ψ` 结合，作平面近似：`Δx ≈ Δs cos(ψ)`、`Δy ≈ Δs sin(ψ)`；精度受航向误差、打滑、轮径和同步影响。姿态估计、轨迹推算、轨迹跟踪闭环是不同功能；绘出轨迹不能据此证明定位精度或轨迹跟踪闭环有效。

实测角速度补偿属于反馈、阻尼还是某种前馈，需看信号从哪里来、进入控制器哪一处，详见第 6 节，不提前替论文定性。

### 5.8 与飞控／云台面试的联系

从控制原理理解，角速度本身就是重要反馈，不只是用于积分出角度。公开飞控系统中可见如下典型层次：

```text
目标姿态 - 当前姿态 → 姿态控制器 → 目标角速度
目标角速度 - 实测角速度 → 角速度控制器 → 执行机构
```

可参考 [PX4 控制框图](https://docs.px4.io/main/en/flight_stack/controller_diagrams)，但这只是公开控制结构示例，不能据此断言大疆产品内部算法、具体传感器或参数。云台也涉及姿态／转动测量、执行机构与相机／机身坐标关系，不能只凭有 IMU 就认为整套稳定控制已经完成。

**面试表述参考：** “项目器件是 MPU9250，硬件有三轴陀螺仪、三轴加速度计和三轴磁力计。陀螺仪直接输出角速度，姿态由运动处理或融合得到。简历描述通过 DMP 读取四元数再转成欧拉角；是否使用磁力计和具体融合配置，需要结合当时驱动确认。我会区分角速度、姿态和 XY 位置，以及厂商算法与个人集成工作。”

## 6. 差速运动学与角速度补偿

### 6.1 正逆运动学、单位与限幅

沿用理想平面模型，车体 X 向前、Y 向左，逆时针航向为正；左右轮有符号线速度 vL、vR，等效轮距 b：

```text
正运动学：v = (vR + vL)/2，ω = (vR - vL)/b
逆运动学：vL_ref = v_ref - ω_ref × b/2
          vR_ref = v_ref + ω_ref × b/2
```

左右等速同向直行、右轮更快左转、等幅反向可作原地旋转，实际驱动符号先统一。本人确认拓展为三轮，第三轮支撑及驱动布置仍需原材料核对；模型假设平面、有效轮径稳定、近似纯滚动，侧滑和地面变化影响等效轮距。这里是运动学，不包含质量、力矩等完整动力学。

若转向量以 m/s 表示，可写 `vL_ref = v_base-u_turn`、`vR_ref = v_base+u_turn`；若它是 PWM，就不能直接当作角速度。轮速超限时单独截断一侧会改变曲率，按比例缩放两轮目标可作为保留速度比的设计方法，仍需结合加速度及可控范围验证。

### 6.2 角速度补偿究竟是前馈还是反馈？

整理材料转述正文把实测陀螺仪角速度加入输出并称为前馈；严格归类需看框图，实测车体角速度用于抑制摆动通常属于反馈／阻尼。通用示例为 `u = u_PD - Kr × ω_measured`，真实正负号还取决于轴向与执行器定义，不能只因片段写加号就判错。

参考曲率产生的 `ω_ff = v_ref × curvature_ref` 才是另一类典型参考前馈。变量 Gyroroll 也不能单独证明实际使用了横滚或偏航速率，必须追踪赋值和安装变换。

## 7. 航位推算、轨迹跟踪与上位机

### 7.1 位姿推算与误差量级

材料附录用编码器速度与 IMU 航向进行 `V cos(th)`、`V sin(th)` 积分，属于平面航位推算；不能仅因两种数据共同使用，就称为已实现 EKF／卡尔曼融合。

已有的离散更新可按距离与区间中点航向改写为下列背景方案，不代表原附录已采用：

```text
ΔsL = ΔCL × π × DL / NL；ΔsR = ΔCR × π × DR / NR
Δs = (ΔsL + ΔsR)/2
Δψ = wrapToPi(ψ_imu[k] - ψ_imu[k-1])
ψ_mid = ψ_imu[k-1] + Δψ/2
x[k] = x[k-1] + Δs cos(ψ_mid)
y[k] = y[k-1] + Δs sin(ψ_mid)
```

角度均在一致参考系内，三角函数使用弧度；编码器角增量 `(ΔsR-ΔsL)/b` 也可用于一致性检查，但正式融合方案需另查。轮径、打滑、航向和时间同步误差都会积累，不能把“IMU 读数”直接等同于准确 XY。

小固定航向偏差 δψ 下，距离 L 对应横向误差约 `Lδψ`：1° 偏差走 10 m 约为 0.175 m。纯加速度双积分对固定偏置 b_a 的位置误差约为 `0.5b_a t²`，还会受姿态误差引入的重力投影影响。这些是原理估算，不是项目实测指标；滤波不能单独消除所有累计误差。

### 7.2 跟踪误差的参考系

参考位姿 `(xr,yr,ψr)`、估计位姿 `(x,y,ψ)`，将参考减估计的位置差旋转到车体坐标，可定义：

```text
ex = cos(ψ)(xr-x) + sin(ψ)(yr-y)
ey = -sin(ψ)(xr-x) + cos(ψ)(yr-y)
eψ = wrapToPi(ψr-ψ)
```

ex 为纵向误差、ey 为横向误差。轨迹跟踪误差不是相邻采样时刻的位置增量；世界坐标误差和车体误差也不能配上彼此不匹配的控制律。

### 7.3 预设目标点跟踪

整理材料描述“取下一目标点 → 先调整方向 → 再前进 → 到达后切换目标”的实现路线：

```text
dx = x_goal-x，dy = y_goal-y
ψ_goal = atan2(dy,dx)
distance = sqrt(dx²+dy²)
angle_error = wrapToPi(ψ_goal-ψ)
```

应使用位置／角度容差、必要的稳定时间、超时与退出条件，而非浮点相等判断。点间折线的拐角可能需要停车或降速，不自动具备平滑曲线跟踪、在线规划或自主避障能力。

### 7.4 有限时间控制：理论、仿真与实机分别说明

渐近收敛是在时间趋于无穷时趋近目标；有限时间控制在满足模型条件时于有限理论时间达到平衡。标量背景例：

```text
z_dot = -k × sign(z) × |z|^a，k>0，0<a<1
T = |z0|^(1-a) / (k(1-a))
```

负数的分数幂需使用保符号形式，不能直接调用 `pow(负数,小数)`。离散采样、噪声与饱和下，应验证误差容差带和实际约束，不把理想精确归零当成物理精度承诺。

材料转述论文先使航向误差收敛，再处理位置；某位置控制式含 `1/ωr`，因此不能直接用于 ωr=0 的直线段，需要另处理。给出的仿真 vr=1.5 m/s、ωr=1 rad/s，对应半径 1.5 m；图文报告约 0.4 s 航向、约 3 s 位置趋近零，都只属于该仿真配置。

材料还指出初始误差数值、阶段切换与展示的 MATLAB／附录片段存在不一致；完整模型尚未直接读取。不要据此声称理论控制律已原样移植或实车达到相同收敛时间。

### 7.5 RBF 神经网络滑模：只作理论补充

RBF 使用如 `h_j(x)=exp(-||x-c_j||²/(2b_j²))` 的径向基，输出为加权和；材料描述以横向误差及其变化率为输入、5 个隐层节点、1 个输出估计不确定项。滑模示例趋近律为 `s_dot=-ε sign(s)-ks`。

切换控制可能抖振，边界层等平滑措施有鲁棒性与精度取舍；RBF 效果还依赖输入范围、权重更新、残差与稳定性条件。整理材料没有完整可复现的在线更新和实机对照证据，因此不列为已部署神经网络控制，不把“全局稳定”等文字替代证明。

### 7.6 HC-12、数据帧与 Qt

HC-12 是无线串口透传模块，不因论文框图写“蓝牙”就成为蓝牙。MCU 端 UART、无线设置与空中吞吐都要匹配；电脑 COM 口通常还涉及 USB-UART 桥接，裸 HC-12 不自动提供 USB。

| 功能 | 整理材料转述的数据头 | 后续字段 |
| --- | --- | --- |
| 状态上报 | `0xEB90` | x、y、th、v，2 字节校验，`0x5A` 帧尾。 |
| 启动 | `0xEB91` | start 字段、2 字节校验及帧尾。 |
| 停止 | `0xEB92` | end 字段、2 字节校验及帧尾。 |

表中数值／命令字段均列为 8 字节，但实际编码、字节序、填充和校验算法未完整说明，不能直接当作 double 或某种 CRC。ASCII start、end 分别只有 5、3 字节，固定 8 字节仍需约定填充。

按表面长度，状态帧为 `2+4×8+2+1=37 B`。材料列 `Serial_Init(115200)`；假设 8N1，理论串口上限 11520 B/s，100 帧/s 占 3700 B/s，仍需另评估无线和缓冲，不能视作已测可持续吞吐。

串口及 Qt 接收均按字节流组包，处理半帧、多帧、校验和重同步。QSerialPort／readyRead 加缓存是通用实现思路，完整 Qt 源码未展示，不断言采用了具体类或绘图库。GUI 更新在 GUI 线程，耗时处理不能阻塞事件循环；显示刷新率可低于采集／控制频率。

轨迹曲线只显示收到的估计坐标，验证精度需要独立真值，不能把同一份里程计既当反馈又当唯一正确性证据。

## 8. 软硬件联合排障与验证

可以准备但不能当作已发生的故障：ADC 通道饱和、舵机抖动、电机干扰 IMU、电源压降导致复位、UART 丢帧、坐标轴符号错误、积分漂移。

排查按证据分层：电源／接线 → 原始采样 → 数值转换 → 控制量 → 执行器 → 运动结果。优先记录同一时间轴上的传感器、error、目标／实际轮速、控制输出、姿态和任务／中断耗时，再决定是硬件噪声、控制参数还是调度问题。

若负压系统使用风机，应按实际电路说明负载、电源预算与噪声影响；没有测量不能直接认定它是某次故障根因。

### 8.1 10 ms 控制与多时间尺度调度

整理材料给出的轨迹控制周期是 10 ms，即 100 Hz；这不等于全部传感器、显示和电流内环都按同一周期执行。定时器更新频率可用 `f_update=f_TIM/((PSC+1)(ARR+1))`，需从实际时钟树确定 f_TIM；PWM 还要考虑计数模式，不能一律把总线频率直接代入。

采集、控制、通信、显示和温湿度更新应按各自时限组织；这是调度改进思路，尚未核实完整实现。材料中的中断内无限等 DMP、较多 printf、或把约 75 ms 传感器等待塞进控制中断，都可能使 10 ms 预算失控。可用有界读取、数据有效标志、缓存及后台发送，按平台需求安排 DMA 等手段。

固定用 0.01 s 积分的前提是节拍确实满足；通过调试引脚和示波器测最长执行时间、周期抖动，检查采样时间戳。共享多字段快照也需保护，volatile 不保证整份状态一致。

### 8.3 验证优先级与记录指标

先确认反馈符号和单位，再做单轮测速标定、轮速阶跃、转向与整车轨迹。低速抖动检查计数量化与死区，弯道摆动检查噪声、延迟与补偿符号，轨迹跳变检查回绕、时间戳与拆帧；这些是排查方法，不是补造故障经历。

记录目标／实测轮速、控制量与饱和、航向漂移、横向误差、重复闭环终点误差、最长控制耗时及通信错误。轨迹验证用已知距离／路线或外部测量，注明路面、车速、供电、重复次数及方法；没有原始记录不补写改善百分比或精度。

### 11.2 MPU9250、姿态解算与控制可能追问

| 问题 | 简短回答／核对方向 |
| --- | --- |
| 用的是六轴还是九轴陀螺仪？ | 型号 MPU9250 是九轴组合，陀螺仪本身三轴，加上三轴加速度计和三轴磁力计。硬件九轴不等于程序一定使用九轴融合。 |
| 陀螺仪直接测角度吗？ | 测角速度，原始整数按量程换算，结合采样时间与校准参与姿态估计；不是直接输出 XY 位置。 |
| 怎么将原始数据换成角速度？ | 读取有符号数，按当前量程的灵敏度换算，例如 ±250°/s 时 131 LSB/(°/s)，不是随意固定一个比例。 |
| 静止时角度为什么还变化？ | 零偏和噪声等经过积分累计，温漂和 Δt 误差也会影响；静止校准有帮助但不保证消除所有工况漂移。 |
| 为什么加速度计静止不是零？ | 静止支撑时有重力参考响应，模长通常约 1g；方向随安装变化，不能全部当零偏减掉。 |
| 加速度计能修正 yaw 吗？ | 一般仅靠重力无法确定绕重力轴的绝对航向，六轴融合仍可能有 yaw 漂移，需要其他可信参考或约束。 |
| 有磁力计，为什么航向还不稳？ | 要确认是否实际读取并参与融合、坐标和校准是否正确，评估电机、电磁赛道与电流等干扰。 |
| 四元数的四个数是什么？ | 共同表示三维姿态的参数，不是四个旋转轴；单位约束、坐标方向与转换顺序要一致。 |
| 为什么内部用四元数，显示用欧拉角？ | 四元数适合三维姿态运算，欧拉角直观；转换不消除漂移，欧拉角仍有奇异性和范围跳变。 |
| DMP 是什么，是自己写的吗？ | 芯片运动处理单元，需配套固件／驱动配置；说明厂商算法与自己读取、转换、校准、控制集成的边界。 |
| 用了 DMP 就是九轴绝对航向吗？ | 不能直接推出，需查固件输出模式、磁力计参与情况及参考系；不能只凭芯片型号推断实际融合算法。 |
| 为什么采样时间重要？ | 积分直接使用 Δt，任务延时不等于精确采样周期，FIFO 样本时刻也不等于一次性读出时刻。 |
| XYZ 角速度能直接分别积分成欧拉角吗？ | 单轴／近似水平可作简化，一般三维运动的机体角速度与欧拉角速率不同，需运动学变换或四元数更新。 |
| IMU 怎么参与小车控制？ | 电感给循迹误差，编码器给轮速／里程，陀螺仪给转动速度，估计航向可用于轨迹推算；用途和控制位置需看实际框图。 |
| 为什么不能说读 IMU 就有准确 XY？ | 位置需要后续运动学／导航计算与其他信息；航向误差、打滑、轮径及积分时序都会影响里程计。 |
| 和飞控、云台有什么联系？ | 角速度和姿态分别可作快速控制反馈与姿态目标比较的依据；以公开框图解释原理，不推断大疆内部实现。 |
